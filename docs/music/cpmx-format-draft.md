# `.cpmx` — CrossPoint Music Format (DRAFT v0)

**Status**: draft/brainstorm — nothing frozen. Freeze as v1 at the end of Phase 2 (see [PLAN.md](PLAN.md)). Modelled on the `book.bin`/`section.bin` conventions in [file-formats.md](../file-formats.md): little-endian, version byte first, bump version before any structural change.

## Design goals

- Measures are self-contained pre-engraved units with known widths → firmware layout is measure-packing only ("word wrap" with measures as words).
- Streamable from SD: firmware never needs the whole file in RAM; seek table up front.
- Coordinates are measure-local, in **staff-space units** (1 unit = 1/4 of the gap between staff lines, SMuFL convention) so one file serves all rasterized staff sizes.
- No on-device curve math: slur/tie split variants are pre-generated by the converter.

## Sketch (all TBD)

```
Header:
  magic "CPMX", u8 version
  u16 measureCount, u8 staffSize hints, title/composer strings (offsets)
  u32 seekTable[measureCount]     // file offset per measure record

SystemHeaderBlock[]:              // one per unique (clef, keySig) combo
  primitives to draw at each system start; measures reference by index

MeasureRecord:
  u16 width                       // staff-space units, at nominal size
  u8  systemHeaderIdx             // clef/key context if this starts a system
  u8  flags                       // has split-slur variants, starts repeat, ...
  PrimitiveList (default)
  PrimitiveList (split-at-start)  // optional, only if flags say so
  PrimitiveList (split-at-end)    // optional

Primitive (tagged union, u8 type):
  GLYPH  { u16 smuflCodepoint, i16 dx, i16 dy }
  LINE   { i16 x1, y1, x2, y2, u8 thickness }   // stems, barlines, staff lines?
  BEAM   { quad/parallelogram coords }
  CURVE  { precomputed polyline points }        // slurs/ties, flattened offline
  TEXT   { strOffset, i16 dx, dy, u8 fontId }   // lyrics, tempo, chord symbols (later)
```

## Open questions

- Staff lines: per-measure primitives (simple, redundant) or drawn by firmware from measure width (smaller files)? Leaning firmware-drawn.
- Alignment: keep all multi-byte fields naturally aligned or `memcpy` everything (RISC-V faults on unaligned access — see root CLAUDE.md).
- Fixed-point precision for staff-space coords (i16 with 1/16-unit fraction?).
- Multi-staff systems (v2): per-staff primitive lists inside one MeasureRecord with a shared width.
- Where it lives on SD: alongside the source file, or under `.crosspoint/` like other caches? (It's a conversion artifact, not a cache — leaning alongside.)
